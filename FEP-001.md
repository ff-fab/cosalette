# FEP-001: Lazy Store Resolution

**Status:** Proposed **Date:** 2026-04-20 **Author:** cosalette-apps maintainer
**Target:** cosalette >= 0.4.x

## Problem

`App(store=...)` only accepts a concrete `Store` instance at construction time. This
forces adopters to resolve the store path eagerly — before settings are available —
which conflicts with the `@app.on_configure` lifecycle designed to eliminate eager
settings access.

### Concrete example (gas2mqtt)

```python
# Current: eager settings crash --help when env vars are absent
settings = Gas2MqttSettings()
_store = JsonFileStore(settings.state_file) if settings.state_file else NullStore()
app = App(name="gas2mqtt", store=_store, settings_class=Gas2MqttSettings)
```

The `state_file` path comes from the settings model, which requires environment
variables. Running `gas2mqtt --help` fails because the settings class is instantiated at
import time.

### Current workaround

Extract store path resolution into a standalone function that reads a single env var or
falls back to XDG defaults — bypassing the settings model entirely:

```python
def resolve_store_path() -> Path:
    """Resolve store path from GAS2MQTT_STATE_FILE or XDG default."""
    from_env = os.environ.get("GAS2MQTT_STATE_FILE")
    if from_env:
        return Path(from_env)
    return Path(os.environ.get("XDG_DATA_HOME", "~/.local/share")).expanduser() / "gas2mqtt" / "state.json"

app = App(name="gas2mqtt", store=JsonFileStore(resolve_store_path()), ...)
```

This works but duplicates path logic between the standalone resolver and the settings
model.

## Proposed solutions

### Option A: Callable store factory (recommended)

Accept `Callable[..., Store]` in addition to `Store` for the `store=` parameter. The
factory is called during the bootstrap phase — after settings resolution but before
device startup — with DI for the resolved settings instance.

```python
def make_store(settings: Gas2MqttSettings) -> Store:
    if settings.state_file:
        return JsonFileStore(settings.state_file)
    return NullStore()

app = App(name="gas2mqtt", store=make_store, settings_class=Gas2MqttSettings)
```

**Implementation sketch:**

```python
# In App.__init__
self._store_factory: Callable[..., Store] | None = None
if callable(store) and not isinstance(store, Store):
    self._store_factory = store
    self._store = None
else:
    self._store = store

# In App._run_async, after settings resolution
if self._store_factory is not None:
    plan = build_injection_plan(self._store_factory)
    kwargs = resolve_kwargs(plan, {type(resolved_settings): resolved_settings, Settings: resolved_settings})
    self._store = self._store_factory(**kwargs)
```

**Advantages:**

- Minimal API change — `store=` stays a single parameter
- Factory receives DI (settings, adapters) so it can use any settings field
- Backward compatible — existing `Store` instances still work
- No new lifecycle phase needed

**Disadvantages:**

- Slightly more complex `__init__` logic
- Factory must be sync (store creation shouldn't be async anyway)

### Option B: Store setter on App

Expose `app.store = ...` as a property setter, usable from `on_configure`:

```python
@app.on_configure
def setup(settings: Gas2MqttSettings) -> None:
    app.store = JsonFileStore(settings.state_file) if settings.state_file else NullStore()
```

**Disadvantages:**

- Mutation after construction is error-prone
- Ordering: `on_configure` runs after adapter resolution but the store must exist before
  device stores are created — tight coupling to lifecycle ordering
- Breaks the "composition root declares, framework runs" principle

### Option C: Store as DI-injectable in on_configure

Add `Store` to the `on_configure` injection providers, with a default `NullStore` that
can be replaced:

**Disadvantages:**

- Semantic mismatch: `on_configure` receives a store it's supposed to _set_, not _use_
- Requires a swap/replace mechanism that doesn't exist

## Recommendation

**Option A** — callable store factory. It's the smallest API surface change, fully
backward compatible, and follows the existing `init=` factory pattern that adopters
already understand.

## Impact

- gas2mqtt: eliminates `resolve_store_path()` workaround
- Any future app with settings-dependent store paths benefits
- No breaking changes to existing apps
